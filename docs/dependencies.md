# Dependencies

This page lists every direct dependency of the app and its packages and
every native component compiled into the offline engine: the version, the
licence, and why it's there. Transitive Dart packages appear on the app's
licences page (**Settings > About > Open-source licenses**) and in
`flutter pub deps`.

## Licence summary

- **Default build** (GitHub releases, F-Droid, the Play bundle): MIT,
  BSD-2-Clause, BSD-3-Clause, Apache-2.0, Zlib and MPL-2.0 (Mozilla's
  bergamot-translator). Nothing is GPL or proprietary.
- **Play variant** (`tool/play_prepare.sh`; not released, build it
  yourself): the default build plus Google ML Kit
  text recognition. Its Dart wrapper is MIT, but the native SDK is
  **proprietary** (ML Kit terms) and pulls in Play services and Google's
  data transport. Those rows are flagged below.
- `packages/mlkit_translator` (ML Kit translation) is kept for reference
  only. No build depends on it.
- `.github/workflows/license_check.yaml` allows MIT, BSD-2-Clause,
  BSD-3-Clause and Apache-2.0 for pub dependencies. It runs on pull
  requests to `main` and pushes to `main` that change `pubspec.yaml` or
  `pubspec.lock`, with the Flutter SDK and Very Good CLI's
  `packages check licenses` (the shared Very Good workflow resolves
  dependencies with `dart pub`, which can't resolve a Flutter app).

## Regenerating the tables

The tables between the markers below are generated by
[`tool/list_dependencies.py`](../tool/list_dependencies.py). It needs no
network: it reads the pubspecs, the lock files, the `LICENSE` files in the
pub cache and the submodule checkouts.

```sh
flutter pub get                               # root lock and pub cache
bash .github/scripts/packages.sh get          # each package's (git-ignored) lock
bash tool/fetch_native_deps.sh                # native checkouts
python3 tool/list_dependencies.py --write     # update this page
python3 tool/list_dependencies.py --check     # exit 1 if this page is stale
```

Run it after changing a `pubspec.yaml`, a lock file, a submodule or
`tool/play_prepare.sh`. The "Why" texts live in the script's `PURPOSE`
table; a new dependency shows up as "(undocumented)" until you add one. The
native rows compare the licence file of each checkout with
`packages/bergamot_translator/native/THIRD_PARTY_NOTICES.md` and say so
when a component is missing there or the two disagree.

Versions come from each package's own `pubspec.lock` when it has one (CI
resolves every package on its own), otherwise from the committed root
`pubspec.lock`, which is what the app build uses for everything, path
packages included. Native commits are the gitlinks recorded in git.

## Native code inside mozilla/translations

Besides the submodules above, `mozilla/translations` carries code of its
own under `inference/marian-fork/src/3rd_party/`. It's pinned by the
`translations` commit and listed with its licence in
[`THIRD_PARTY_NOTICES.md`](../packages/bergamot_translator/native/THIRD_PARTY_NOTICES.md):

- Marian (MIT);
- protobuf-lite (BSD-3-Clause);
- yaml-cpp, spdlog/fmt, zstr, cnpy, phf, mio and half_float (MIT);
- pathie-cpp (BSD-2-Clause);
- CLI11 (BSD-3-Clause);
- sse_mathfun, avx_mathfun and threadpool (Zlib).

The library also links LLVM libc++ from the NDK statically
(Apache-2.0 WITH LLVM-exception). Local changes are the two patches in
`packages/bergamot_translator/native/patches/` (MIT).

**Gaps in the notices** (checked on the Linux build of the engine, 17 Oct
2026):

- **zlib 1.2.11** (`marian-fork/src/3rd_party/zlib`, Zlib licence) is
  compiled and linked into `libmozhi_bergamot.so`. Its symbols are in the
  library, but the notices list only the Zlib *licence* (for
  sse_mathfun), not zlib itself.
- **faiss** (`marian-fork/src/3rd_party/faiss`, MIT, © Facebook) is compiled
  by Marian's CMake. No faiss symbols end up in the Linux library. Check
  the Android libraries before deciding whether it needs a notice.
- **CLD2** (Apache-2.0) is being added as a submodule. It needs a row too.

Each addition also needs an entry on the app's licences page
(`lib/app/third_party_licenses.dart`). A test there keeps the page and the
notices in sync.

## Android libraries

- The app module adds `org.jetbrains.kotlin:kotlin-stdlib` 2.3.21
  (Apache-2.0) in `android/app/build.gradle.kts`.
- The plugins bring AndroidX, Kotlin coroutines, Material Components 1.7.0
  (`dynamic_color`) and Tink 1.23.0 (`flutter_secure_storage`). All are
  Apache-2.0, and none is a tracker. See
  [the audit, §1.4](audit/2026-audit.md#14-native-android-dependencies-of-the-plugins-pub-cache-gradle-files)
  for the per-plugin list (as of the audit baseline).
- In the default build, every configuration excludes `com.google.mlkit`,
  `com.google.android.gms`, `com.google.firebase` and
  `com.google.android.datatransport` (`noMlkit`, default `true`). A
  dependency that pulled them in would fail the release build, and CI
  checks every APK with `tool/check_no_google.sh`
  ([Building](building.md#check-an-apk-for-google-code)).

## Not bundled

- **Translation models**: Mozilla's Firefox Translations models (MPL-2.0).
  They're downloaded on request, never shipped, and verified against
  `packages/bergamot_translator/assets/catalog.json`
  ([Offline engine](offline-engine.md#models-and-the-catalog)).
- **Web build**: the Flutter engine and CanvasKit (Skia, BSD-3-Clause) come
  with the Flutter SDK and are served from the build itself
  (`--no-web-resources-cdn`).
